## 2. Original Runtime Problem

During execution of `POST /api/v1/orchestrator/run`, the endpoint returned `HTTP 200 OK`, but runtime logs showed `Search Started | Provider: Exa (Mock Fallback)`. The resulting evidence contained synthetic placeholder domains (`https://docs.example.com/spec`, `https://benchmarks.example.org/analysis`), and `research_result.tools_executed` contained only `["web_search"]`. Real Internet search (Exa) and content extraction (Firecrawl) were not executing.

---

## 3. Root Cause Analysis

1. **Unloaded Environment Settings**: `ToolsSettings` in [`backend/app/core/settings/tools.py`](../../backend/app/core/settings/tools.py) inherited from `BaseSettings` without declaring `model_config = SettingsConfigDict(env_file=".env", env_file_encoding="utf-8", extra="ignore")`. Consequently, `EXA_API_KEY` and `FIRECRAWL_API_KEY` were initialized as empty strings `""` despite being present in `backend/.env`.
2. **Silent Mock Fallback**: When `self.api_key` was empty, `ExaProvider` and `FirecrawlProvider` silently returned fake mock data instead of raising explicit configuration exceptions.
3. **Incomplete ResearchAgent Pipeline**: `ResearchAgent` (`app/agents/research/research.py`) only invoked `"web_search"` for each task and never executed `"web_fetch"` (`ContentTool` / Firecrawl) on the URLs returned by search results.

## 7. Exa & Firecrawl Provider Fixes

- **`ExaProvider`**: Issues direct HTTP POST requests to `https://api.exa.ai/search` using header `x-api-key`. HTTP errors map to `SearchAuthenticationException`, `SearchTimeoutException`, `SearchRateLimitException`, etc.
- **`FirecrawlProvider`**: Issues direct HTTP POST requests to `https://api.firecrawl.dev/v1/scrape` using header `Authorization: Bearer <key>`. HTTP errors map to `ContentAuthenticationException`, `ContentTimeoutException`, etc.
- **Secret Masking**: Logs output `Search Started | Provider: Exa` and `Content Extraction Started | Provider: Firecrawl` with latency and status code. API keys are NEVER logged or exposed.
