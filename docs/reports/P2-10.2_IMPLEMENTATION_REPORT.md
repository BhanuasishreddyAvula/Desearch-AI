## 2. Original Failure & Root Cause

### Original Runtime Failure
During execution of `POST /api/v1/orchestrator/run` after activating real Exa search and real Firecrawl content extraction in P2-10.1, the Research Agent LLM call failed with `HTTP 400 Bad Request` from OpenRouter. The request contained ~260,672 input tokens + 4,096 requested output tokens, exceeding the OpenRouter model context window limit of 262,144 tokens.

### Root Cause
1. **Unbounded Content Inclusion**: Raw Firecrawl-extracted Markdown documents (some over 100,000 characters) were passed wholesale directly into `{tool_outputs}` within the Research Agent LLM user prompt.
2. **Duplicate URL Extraction**: The same URLs were fetched multiple times across separate planner tasks during a single workflow execution, wasting Firecrawl API quota and ballooning prompt token size.

## 5. Implementation Details

### A. Execution-Scoped URL Deduplication
- `normalize_url(url)` standardizes URLs by lowercasing scheme/host, stripping trailing slashes, and removing fragment anchors (`#...`).
- `ResearchContextBuilder` maintains `_extracted_cache: dict[str, dict[str, Any]]` during each research execution.
- If multiple planner tasks select the same candidate URL, the already extracted document is reused from memory. Firecrawl is NOT invoked again.

### B. Per-Source Content Budgeting
- `RESEARCH_MAX_SOURCE_CHARS = 10000` (default ~2,000 words per source).
- `safe_truncate_text()` truncates long Markdown at paragraph (`\n\n`), sentence (`. `), or word boundaries without cutting Unicode code points.

### C. Global Research Context Budgeting
- `RESEARCH_MAX_TOTAL_CHARS = 40000` (default ~8,000 words total across all sources).
- Keeps total prompt size under ~9,000 tokens, leaving over 250,000 tokens of safety headroom.

### D. Provenance Preservation
- Every bounded entry explicitly retains `Title`, `URL`, `Snippet`, `Content`, and metadata.
